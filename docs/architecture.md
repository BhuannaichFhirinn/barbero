## Module Organisation

### `src/core/`

Core contains the most fundamental Boolean utilities. These are the building blocks upon which other logic can be built:

- **`truthy.js`** — `isTruthy` and `isFalsey`. Direct wrappers around JavaScript's truthiness coercion.
- **`compare.js`** — `isEqual` (deep recursive comparison) and `isStrictEqual` (`Object.is` semantics).
- **`parsing.js`** — `parseBoolean`, `isBooleanable`, `isTruthyString`, `isFalseyString`. Semantic boolean recognition from strings and numbers, covering 42 recognised boolean representations (21 truthy, 21 falsy).

### `src/utilities/`

Utilities are higher-level conveniences built on top of standard JS mechanisms:

- **`validation.js`** — Nine functions covering null/undefined checks, type guards (`isArray`, `isObject`, `isFunction`, `isDate`, `isRegExp`), and emptiness checks.
- **`types.js`** — Seven primitive and structural type identity checks: `isNumber`, `isString`, `isBoolean`, `isSymbol`, `isBigInt`, `isPrimitive`, `isClassInstance`.
- **`logic.js`** — `xor` (exclusive OR) and `nand` (NOT AND) Boolean gate operations.
- **`predicate.js`** — Higher-order functions (`allPass`, `anyPass`, `nonePass`, `composePredicates`) for composing predicate functions.
- **`number.js`** — Eleven numeric predicates: `isInteger`, `isFloat`, `isPositive`, `isNegative`, `isZero`, `isEven`, `isOdd`, `isInRange`, `isDivisibleBy`, `isFiniteNumber`, `isNaNValue`.
- **`string.js`** — Ten string content predicates: `isNumericString`, `isAlpha`, `isAlphanumeric`, `isUpperCase`, `isLowerCase`, `isPalindrome`, `isBlankString`, `stringStartsWith`, `stringEndsWith`, `stringIncludes`.

### `src/index.js`

The single entry point. It imports every function from all modules and re-exports them:
1. As **named exports** — supports tree-shaking (`import { isTruthy } from 'barbero'`)
2. As properties on the **default export** `Barbero` object — supports default import and UMD global usage

## Build System

Barbero uses **Rollup 4.x** to produce three distribution formats from the single entry point `src/index.js`.

### Outputs

| File | Format | `exports` setting | Use case |
|------|--------|----------|----------|
| `dist/index.cjs` | CommonJS (`cjs`) | `named` | Node.js `require()` |
| `dist/index.mjs` | ES Module (`es`) | — | Bundlers, native `import` |
| `dist/index.umd.js` | UMD | `named` | Browser `<script>` tag; global `Barbero` |
| `dist/index.d.ts` | TypeScript declarations | — | TypeScript consumers; generated by `tsc` from JSDoc |

### TypeScript Declaration Generation

Barbero ships a `dist/index.d.ts` declaration file alongside its JavaScript outputs. This file is **generated automatically from JSDoc annotations** using the TypeScript compiler in declaration-only mode — no TypeScript source is involved.

A dedicated `tsconfig.declarations.json` at the repo root controls this:

```json
{
  "compilerOptions": {
    "allowJs": true,
    "declaration": true,
    "emitDeclarationOnly": true,
    "declarationDir": "dist",
    "checkJs": false,
    "moduleResolution": "node",
    "module": "es2020",
    "target": "es2020"
  },
  "include": ["src/index.js"]
}
```

The `build` script runs Rollup and then `tsc` in sequence:

```json
"build": "rollup -c && tsc --project tsconfig.declarations.json"
```

The `"types"` field in `package.json` points TypeScript consumers to the generated file:

```json
"types": "dist/index.d.ts"
```

`dist/` is already in the `"files"` array, so `dist/index.d.ts` is included in every published package automatically.

### Plugins

- `@rollup/plugin-node-resolve` — resolves Node.js module paths
- `@rollup/plugin-commonjs` — converts any CommonJS deps to ESM (none currently, but guards future additions)
- `@rollup/plugin-terser` — minifies all outputs

### `prepublishOnly`

The `package.json` `prepublishOnly` script runs `npm run build` automatically before every `npm publish`. This ensures the `dist/` folder is always up to date and consistent with the source at publish time.

## Test Setup

Tests use **Vitest 2.x**. Configuration is in `vitest.config.js`.

- Tests import **directly from source** (`../../src/...`), never from `dist/`
- The `tests/` directory mirrors the `src/` directory structure exactly
- Each source module has a corresponding `*.test.js` file

## Design Decisions

### Why JavaScript, not TypeScript?

Barbero intentionally uses plain JavaScript with JSDoc annotations. This keeps the library simple to contribute to, avoids a compilation step in local development, and produces source that is directly readable without tooling. The JSDoc on every function provides type information for editors that support it.

Barbero does, however, ship a `dist/index.d.ts` declaration file for TypeScript consumers. This is generated automatically from the JSDoc using `tsc --emitDeclarationOnly` — the source remains plain JavaScript and no TypeScript compilation is involved. The distinction is important: the library is not written in TypeScript, but TypeScript users can consume it with full type safety.

### Why Rollup, not Vite or esbuild?

Rollup is the conventional choice for library bundling. It produces clean, minimal output without framework-specific assumptions, and has first-class support for the CJS/ESM/UMD output triad needed for broad consumer compatibility.

### Why three output formats?

- **CJS** — required for Node.js consumers who use `require()`
- **ESM** — enables tree-shaking in modern bundlers; the preferred format for library consumers
- **UMD** — allows direct use in a browser `<script>` tag without a bundler, exposing a global `Barbero` object

### Zero runtime dependencies

Barbero has no runtime dependencies by design. Every function is implemented using only native JavaScript. This keeps bundle size minimal and eliminates transitive dependency risk for consumers.

### Pure functions only

All exported functions are pure:
- No side effects
- No mutation of inputs
- Deterministic — same input always produces same output

This makes the library trivially testable, safe to use in any context, and easy to reason about.
